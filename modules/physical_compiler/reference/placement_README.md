# Pinned QMAP placement reference

This comparison executes placement methods from MQT QMAP commit
`cd8ec9131f99d93ce1601c9a1dcad5c9e09ce31d`.
It covers automatic initial placement, nearest-SLM/site queries, ordered gate
and storage candidate generation, expanding windows, candidate orientation,
lookahead, compatibility-group costs, node heuristics, and final IDS placement
for supplied layers. It does not execute the upstream scheduler, reuse analyzer,
router, or complete compiler.

`placement_reference.py` verifies the exact SHA-256 fingerprints of
`Architecture.cpp/.hpp` and `HeuristicPlacer.cpp/.hpp`. It extracts the original
geometry/preprocessing methods, complete placer class, and complete placer
implementation. Algorithm bodies are unchanged. Private declarations are made
public, external JSON/logging plumbing is stubbed, and an input adapter supplies
SLM objects and layer data.

The two original `getHeuristic` definitions are renamed to
`originalHeuristic`, without changing their bodies. Observation wrappers call
them with unchanged arguments and return their unchanged results. These wrappers
record the complete candidate jobs and every distinct visited option path's
cost, heuristic, and scale factors. The original candidate loops, window
expansion loops, neighbor generation, and IDS execute normally.

The data adapter uses the upstream hash-combine expression for STL containers.
Its geometry units are integer micrometres: this avoids changing the meaning of
the square-root distance proxy and the `reuseLevel` constant. Numeric comparisons
allow `2e-6` relative/absolute tolerance for upstream `float` calculations.
Discrete sites, candidate order, option paths, and final placements compare
exactly.

## Cases and explicit differences

`placement_fixtures.json` supplies 15 cases. Twelve compare equal against the
executed original methods:

- Initial storage filling from either row direction.
- Nearest storage and entanglement queries across multiple SLMs.
- Full candidate generation and reversed gate orientation, retaining the
  upstream `[dis2, dis3]` score metadata for the reversed assignment.
- Square, landscape, and portrait gate-window expansion.
- Occupied gate sites, gate lookahead, and full-array discretization beyond
  the selected candidate window.
- Full and windowed storage candidates, optional reuse, and storage lookahead.

Three cases record deliberate source corrections separately. Their raw
upstream output remains in the oracle and is not replaced by local results:

1. **Next-SLM initial row reset:** upstream switches to row 0 after exhausting
   the first storage SLM during reverse filling. Local filling starts from the
   last row of each subsequent SLM. The recorded first site in SLM 3 is
   `[3,0,0]` upstream and `[3,2,0]` locally.
2. **Full nearest storage column:** upstream assigns the boolean expression
   `abs(column-nearestCol) < minDistance` to `currentDistance`, then stores that
   boolean as the next minimum. The fixture fills column 5; its upstream
   horizontal score scale is `1`, while selecting the actual nearest free
   column produces `4/3`. Candidate lists match, but scores and final placement
   can differ.
3. **Storage points straddling a gate zone in y:** the original y-bound test
   checks only the first point and performs an unsigned subtraction. Storage
   points at y=0 and y=40 with gate zones at y=10 and y=30 select the second
   zone upstream. Checking both points, as the source already does for x,
   gives equal bounds and selects the first declared zone.

Undefined end-iterator dereference and nonterminating exhausted-window inputs
are not executed as ordinary oracle cases. Their local completion behavior is
covered by separate geometry/window tests and documented in ADR 0018.
No fixtures have been removed from the previous routing or staging oracles.

## Reproduce

Run from `modules/physical_compiler` with an external C++20 compiler:

```powershell
uv run --locked python -m reference.placement_reference `
  --cache-dir "$env:TEMP/nadit-qmap-cd8ec913" `
  --cxx "$env:TEMP/nadit-qmap-cd8ec913/compiler-tool/ziglang/zig.exe" `
  --output "$env:TEMP/nadit-qmap-cd8ec913/placement-results.json"

uv run --locked python -m reference.placement_candidate `
  --output "$env:TEMP/nadit-qmap-cd8ec913/placement-candidate.json"
```

The first command records the supplied text input, raw C++ output, compiler
command, generated translation-unit fingerprint, and normalized result for
every case. `--write-oracle PATH` additionally writes a portable oracle with no
local build paths. The checked-in `placement_expected.json` was generated by
this executable; it is not a second handwritten implementation.

The second command compares the twelve matching cases. The three documented
source differences have explicit assertions in `test_source_layout_reference.py`.
No C++ compiler or network access is needed for the regular Python test suite.
